# data/inputs/domains/multifamily: the training-entity registry

The inputs of the dPL `multifamily` training domain: one row per training target (site x timescale x
source family), each with its own cell set, area weights and flow lengths on the region grid. Role: input.
The three tables are generated by the scripts in this folder and are never edited by hand. Static
attributes, LAI and forcing are not duplicated here: the loaders join them by cell key from
`data/inputs/grid/` and `data/inputs/forcing/`. The observation series stay in their stores under
`data/targets/`.

## Files

| File | What | Built by |
|---|---|---|
| `entities.csv` | The registry, 291 entities: the 95 base entities (9 `uf_monthly`, 69 `usgs_daily`, 17 `cdec_daily` = the 15 CDEC watersheds, CLE and CSN), then the `calsim_monthly` family of 196 CalSim3 rim arcs. | `build_entities.py --calsim-arcs` |
| `entity_cells.csv` | Cell sets and area weights: 9,691 rows on 2,849 distinct cells of `data/inputs/grid/grid_cells.csv`. The base set's 5,849 rows (2,652 cells) come first, then the arc family's 3,842 (2,393 cells, 197 of them outside the base set). | `build_entity_cells.py --calsim-arcs` |
| `flowlens.csv` | Flow length from each cell to its entity's outlet, for exactly the 9,691 (entity, cell) pairs. | `build_flowlens.py --calsim-arcs` |

Every target trains as an independent entity. The registry is the superset: a run chooses its entities
at launch (`sacsma dpl train --basins`). Without `--basins` a run takes the 95 base entities; the arc
family loads only when named (`--calsim-arcs train_default` adds the 64 `train_default` arcs, and a run
with family shares names them `calsim=` in `--mt-family-weight`).

## How it is built

From the repository root, in this order. All in `sacsma` except `build_flowlens.py` (`sacsma-gis`).

    python data/targets/dwr_unimpaired/build_uf_depth.py                      # uf_monthly_mm.csv
    python data/targets/cdec/build_fnf_depth.py                               # fnf_daily_mm.csv
    python data/targets/calsim3/build_calsim_arcs.py                          # the three arc tables
    python data/inputs/domains/multifamily/build_entities.py --calsim-arcs
    python data/inputs/domains/multifamily/build_entity_cells.py --calsim-arcs
    python data/inputs/domains/multifamily/build_flowlens.py --calsim-arcs    # appends the arc rows

- Each builder checks its output against gates in the script and rewrites its table in full. The exception
  is `build_flowlens.py --calsim-arcs`: it traces only the arc entities and appends them to the existing
  store, copying the base rows byte for byte. Without the flag it re-traces every entity in the registry.
- Without `--calsim-arcs`, `build_entities.py` and `build_entity_cells.py` write the 95-entity base tables
  (5,849 cell rows) over the tracked ones. The base rows are byte-identical either way.
- `build_calsim_arcs.py` reads the registry's 95 base rows. Starting without a registry, run
  `build_entities.py` once without the flag first.
- The first five builders need only tracked files (LFS included) and reproduce their tables byte for
  byte. They read `data/targets/` (`usgs`, `cdec`, `dwr_unimpaired`, `callite/fnf_11obs_monthly.csv`,
  `calsim3`), `data/inputs/calsim3/` (crosswalk, `CalSim3_Merged`), `data/inputs/domains/15cdec/`
  (`basin_area.csv`, `SACSMA_15CDEC.geojson`) and `data/inputs/grid/`. UF pour points are hand-maintained
  in `data/targets/dwr_unimpaired/uf_gauges.csv`.
- `build_flowlens.py` needs `rasterio` and the DIR and ACC rasters of four 10-degree HydroSHEDS v2 tiles
  (8 files, about 6 GB), downloaded on demand to `tmp/hydrosheds/` with size validation (`--tiles-dir`),
  not in git. `--calsim-arcs` reads the tiles already there. It imports no geopandas and nothing from the
  package: the raster and vector GDAL stacks must stay in separate processes.
- Tier 2 runs the same tracer, for the arcs no trained entity lists (footprint-exit mode). Given
  `sacsma dpl calsim tier2 <run> --trace-python <python of the sacsma-gis environment>`, it calls
  `build_flowlens.py --trace-cells CELLS_CSV OUT_CSV` in a subprocess. Without `--trace-python` those arcs
  get straight-line x 1.5 lengths.

## entities.csv

| Column | Meaning |
|---|---|
| `entity_id` | `<family>_<site>`, unique (`uf_06`, `usgs_11258000`, `cdec_SHA`, `cs_I_ALMNR`) |
| `family`, `timescale` | Loss family and its native timescale |
| `site_id`, `name` | Site identity (read `site_id` with `dtype=str`) |
| `delineation` | `arcs` (union of `CalSim3_Merged` polygons), `usgs_gpkg`, or `sacsma_15cdec_gis` (the Tulare 4: the original SAC-SMA boundary polygons; no CalSim polygons exist) |
| `arcs` | Semicolon list of `I_*` nodes |
| `area_mi2` | The observing site's own drainage area (divides volume into depth). For a UF entity: the sum of its CalSim arc areas |
| `area_mi2_swat` | Appendix A SWAT model area, from `data/targets/dwr_unimpaired/uf_gauges.csv` (7 of the 9 UFs; UF 6 and UF 7 have no usable single model) |
| `outlet_lat`, `outlet_lon`, `outlet_source` | Pour point. Null for `uf_07` (no gauge exists) and for the arcs |
| `record_start` | True start of the source record: UF = first published month (WY1922), USGS = `first_obs`, CDEC = the earlier of the advertised CDEC start and the first day of the tracked store |
| `train_start`, `train_end` | The training window (for USGS it equals the record window) |
| `n_obs` | Valid observations in the window, counted from the raw store |
| `obs_store` | `<path relative to data/>:<column>` of the target series (below) |
| `flags` | Caveats, semicolon list (below) |

The registry holds no series. `obs_store` points at each entity's target:

| Family | `obs_store` | Note |
|---|---|---|
| `usgs_daily` | `targets/usgs/flow_daily.nc:flow_mm` | Already depth |
| `cdec_daily`, the 15 watersheds | `targets/cdec/gage_15cdec.csv:flow` | Already depth |
| `cdec_daily`, CLE and CSN | `targets/cdec/fnf_daily_mm.csv:depth_mm` | cfs to mm/day, negative days dropped; built by `data/targets/cdec/build_fnf_depth.py` |
| `uf_monthly` | `targets/dwr_unimpaired/uf_monthly_mm.csv:depth_mm` | TAF to mm/month at the CalSim arc-sum areas, all 18 arc-mapped UFs, full WY1922-2014 record; built by `data/targets/dwr_unimpaired/build_uf_depth.py` |
| `calsim_monthly` | `targets/calsim3/calsim3_inflow_monthly_mm.csv:depth_mm` | Kept only on the months of `data/targets/calsim3/arc_obs_mask.csv` |

Training windows are never baked into a series: `record_start`, `train_start` and `train_end` own the
windowing at load time.

De-duplication, applied at build time. A watershed does not train at both daily and monthly timescales
unless its daily record is short (starts about 2000 or later). Eleven monthly twins of long-record CDEC
dailies are built and then dropped: UF 8, 9, 11, 14, 15, 16, 18, 19, 22 and both `obs11_monthly` rows (SHA
= the SIS daily; TNL = the CLE daily at 96 % shared area). The short-daily pairs stay: `uf_13`/`cdec_CSN`
(CSN from 1999-04) and `uf_06`/`cdec_BND` (SBB from 1999-05). The twin and record start of each drop are
in `DEDUP_DROPS` of the builder; record completeness was verified against `gage_15cdec.csv` and
`fnf_daily.csv` of `data/targets/cdec/`. A second list, `TARGET_DROPS`, drops for target validity and is
empty.

Flags are annotations for readers: no code branches on them. Footprint and target choices live in the
builder (`EXTRA_ARCS`, `TRIM_ARCS`, `TARGET_DROPS`).

| Flag | On | Meaning |
|---|---|---|
| `train_only` | ISB, PNF, SCC, TRM | The Tulare 4 |
| `polygon_2.6pct_above_published_area` | TRM | `area_mi2` keeps the published 561 as the depth basis |
| `outlet_below_delineation` | `uf_10`, `cdec_BND`, `cdec_FOL`, `cdec_MKM`, `cdec_MRC`, `cdec_ORO` | The gauge or dam sits 5 to 13 km below the delineation |
| `obs_includes_valley_floor`, `no_gauge_composite` | `uf_07` | A composite of east-side creeks with no gauge |
| `obs_routed_through_lakes` | `uf_03` | See "Know before using" |
| `calsim_ref_wetter_summers` | `uf_10` (Bear) | |
| `daily_runs_6pct_below_monthly` | `cdec_CSN` | |
| `fnf_computed_at_trinity_dam` | `cdec_CLE` | |
| `footprint_includes_valley_node` | `cdec_BND` | The cell set includes the series-less `I_SRBB_VAL` node, because the Bend Bridge FNF drainage covers the valley floor between the rim margin and the gauge. `area_mi2` keeps the published 8,900 |
| `footprint_excludes_below_gauge_arcs` | `cdec_YRS` | The two Deer Creek arcs `I_DER001`, `I_DER004` (64 mi²) join the Yuba below the Smartville gauge and are trimmed from the cell set. `area_mi2` keeps the published 1,108 |
| `tier_<A-F or X>` | arcs | The arc's record tier, from `data/targets/calsim3/arc_hierarchy.csv` |
| `train_default` | 64 arcs | Tier A and not a duplicate of an entity: 25,523 arc-months |
| `duplicates_<entity>` | 7 arcs | The arc is a single-arc training entity: I_SHSTA, I_TRNTY, I_MLRTN, I_MCLRE, I_NHGAN, I_PTH070, I_ESTMN |
| `training_usgs_<gid>` | arcs | Built from a registry USGS gauge (9 of the tier-A arcs) |

The `calsim_monthly` family has one entity per CalSim3 rim `INFLOW` arc with a series and a
`CalSim3_Merged` polygon (the below-rim `EXCLUDE_ARCS` and the polygon-less `I_RUB002`, `I_JBP006`,
`I_FSL012` have none). `entity_id` is `cs_<ARC>`, `site_id` and `arcs` the arc, `delineation` `arcs`,
`area_mi2` its unrounded `SQ_MI` (the depth basis of the store). The mask is the arc's own gauge record:
the listed period minus the report's correlation-extension years, inside WY1950-75 and WY1986-2015 only,
so the WY1976-85 holdout never enters. `train_start` and `train_end` are 1949-10-01 and 2015-09-30. `n_obs`
is the arc's mask months: 0 for donor-split, proportioned, reservoir-without-record and no-record arcs,
which the loader refuses if selected.

## entity_cells.csv

| Column | Meaning |
|---|---|
| `entity_id` | Registry key |
| `key`, `lat`, `lon` | Region grid cell (key normalized to 5 decimals) |
| `overlap_mi2` | Area of cell square ∩ delineation: the aggregation weight. Normalize per entity |

Weights come from square-overlap mapping of the `CalSim3_Merged` polygons (`arcs`), the delineated USGS
watersheds (`usgs_gpkg`, `data/targets/usgs/usgs_watersheds.gpkg`) or the original SAC-SMA boundary
polygons (`sacsma_15cdec_gis`, `data/inputs/domains/15cdec/SACSMA_15CDEC.geojson`). The table replaces
the per-domain `hruinfo` tables as the aggregation basis of entity training. Outlet coordinates are in the
registry only.

Cell basis. The dropped monthly twins contribute no cells of their own (their cells are their daily
twins'; TNL's extra `I_LWSTN` cells are those of `usgs_11525500`). The Tulare polygons reach 8 edge cells
beyond the `15cdec_grid` cell sets. The `I_SRBB_VAL` valley cells of `cdec_BND` all serve `uf_06` as well.
`uf_03` holds 93 cells, 49 of which no other entity uses (the other 44 are shared with the three in-basin
USGS gauges and with edge overlaps of `uf_02` and `uf_04`). The two Deer Creek cells below the YRS gauge
are not in the store. A run's basis is the union over the entities it selects (2,603 without `uf_03`).
The full-rim basis (every cell touching a rim polygon, plus USGS and Tulare) is 2,847 cells. Static
attributes are complete: the grid tables cover all 4,410 cells.

## flowlens.csv

| Column | Meaning |
|---|---|
| `entity_id`, `key` | As in `entity_cells.csv` |
| `flowlen_m` | Traced channel distance (m) to the entity outlet, on the HydroSHEDS v2 1-arcsec flow directions (TanDEM-X basis). 0 at the outlet cell, which gives an identity unit hydrograph |
| `method` | `channel`, `center` or `fallback` |

- Start pixel. Each cell starts at its main-channel pixel: the highest-accumulation pixel in the cell
  square whose path reaches the outlet (capped at 1.3 times the entity area, since a pixel carrying more
  water than the watershed cannot drain to its outlet). `center` marks a start at the cell centre (159
  base rows). The within-cell hillslope delay belongs to the cell's runoff response, not to routing.
- Outlet snap. The outlet moves to the nearest pixel (within about 2 km) whose implied upstream area is
  within 0.2 to 5 times the registry `area_mi2`. Nearest in band, not the patch maximum: below a dam the
  maximum sits on the same river a few km downstream.
- `uf_07` (a composite with one outlet per creek) traces each cell to where its path leaves the entity
  footprint. The arcs have no outlet coordinate and are traced the same way, which is also tier 2's
  convention for arcs.
- `fallback` (1,362 base rows, 5.9 % of the base set's area weight; 0.8 % for the arcs) is the
  straight-line distance times the entity's median traced sinuosity, for cells none of whose candidates
  drain through the outlet: below-outlet valley cells, edge slivers of the square overlap, basins smaller
  than a cell. The builder prints the share per entity (worst: a few USGS basins of 2 to 10 cells, and
  `uf_21` at 29 % with its outlet at 0.75 times its area).
- Precedents: the channel-pixel convention follows the coarse-grid upscaling tradition (COTAT's outlet
  pixel with an area threshold, [Reed 2003](../../../../docs/references.md#reed2003); Dominant River
  Tracing, [Wu et al. 2011](../../../../docs/references.md#wu2011drt)). The outlet snap uses the
  upstream-area agreement test of the [HydroSHEDS](../../../../docs/references.md#hydrosheds2) authors.

## Checks

- Registry gates: 9, 69 and 17 base entities per family; 3,240 DWR site-months (9 UFs x 360; 6,480 before
  the de-duplication) and 821,412 USGS gauge-days; CLE area 692.86 mi²; no `record_start` after
  `train_start`; only `uf_07` without an outlet; 196 arcs, 64 `train_default`. The UF pour points copied
  from `data/targets/cdec/stations.csv` are checked against it.
- Cell weights. The overlap sum of each base entity reproduces its footprint's reference area to +0.14 %
  at worst (`uf_10`; the build asserts < 0.2 %). The sums equal the polygons' true geometric areas; the
  residual is mostly the `SQ_MI` attributes running 0.05 to 0.12 % below geometric area, plus slivers
  where arcs overlap (largest pairwise overlap 1.4 % of the smaller arc; ≤ 0.04 % at entity level).
- Arc cells. The overlap sum equals the polygon's true area to 1e-9 and departs from `SQ_MI` by -3.1 to
  +1.5 % for single arcs (55 of 196 beyond 0.2 %; the attribute error averages out in multi-arc
  entities). The 7 duplicate arcs reproduce their entity's cells exactly.
- The Tulare mapping reproduces the `15cdec_grid` weights it replaces at r ≥ 0.99 on the common cells.
- Flow lengths. The snapped accumulation over the registry area lands at 0.75 to 1.11, median about 1.00.
  The archived CADWR flow lengths of `15cdec_grid` are reproduced at r 0.977 to 0.992 with a median ratio
  of 0.97 to 1.06 in all 15 watersheds except MKM (1.18: its archive was measured to a reference point
  about 13 km short of the dam). Median sinuosity runs 1.0 to 1.6 in small basins and 2.0 to 2.3 in the
  large dendritic ones (SHA, BND, `uf_06`). The arc build re-traces `uf_07` and asserts that its stored
  rows are reproduced exactly.

## Know before using

- caution: the sums of `overlap_mi2` are not the registry `area_mi2`, which is the observing site's
  published area.
- caution: `uf_03` (Cache Creek above Rumsey) is observed below Clear Lake and Indian Valley, while its
  four arcs are the inflows CalSim routes through those lakes itself (+16 % volume, r 0.877 against the
  observation). A lake-free cell parameterization can fit it only by learning the lakes' storage and
  evaporation into the runoff parameters. The row is kept so that a run without the USGS family can still
  supervise the Cache Creek cells; a run with the in-basin USGS gauges can leave it out with `--basins`.
- caution: arc flow lengths run shorter than an outlet-snapped trace (the 7 duplicate arcs: mean 0.49 to
  0.87 of their entity's length, r 0.06 to 0.71). Paths along a footprint edge exit early.
- Some outlets sit a few km outside their polygons (dam and valley-floor stations below the delineation).
  The coordinates are the stations' own and are kept.
- `I_RUB002` (in FOL's arc list) has no `CalSim3_Merged` polygon: its terrain was dissolved into
  `MFA025`, so coverage is complete.
